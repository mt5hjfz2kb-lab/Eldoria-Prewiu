## Research → applied/deferred decision

- [Unity orthographic camera API](https://docs.unity3d.com/ScriptReference/Camera-orthographicSize.html) and canonical `docs/VALORIA_CAMERA_EXPANSION_PLAN_V1.md`: orthographic size is vertical half-extent; horizontal coverage depends on aspect. **Applied**: separate strategic/city/detail framing inspection, plus measured runtime home 9.1; keep portrait pan and original 9–19 range. Do not arbitrarily scale city geometry. A separate runtime-home capture checks the actual starting scale.
- [GDC: The Art of Diablo 3](https://gdcvault.com/play/1015306/The-Art-of-Diablo): fixed-camera visual language can retain painterly/material richness and must serve gameplay readability. **Applied**: retain canonical Hero/functional source detail and controlled stone/wood/blue accents; no flat toon/cel-shaded simplification.
- [Blender 5.2 UV editing](https://docs.blender.org/manual/en/5.2/modeling/meshes/uv/editing.html): reserved atlas/trim UV zones are feasible for a later authored source system. **Deferred**: the previous full authored rebuild and first atlas lost richness or became saturated. No unverified atlas rollout from that visually failed proof.
- [Unity URP custom lighting](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/use-built-in-shader-methods-lighting.html): shared light/shadow response remains preferable to an unlit global recolor. **Applied**: use already certified PBR response/source CC0 maps for a visual-only continuous road/civic stone interface and bounded cultivated context, tested at all official cameras.
- [Unity URP decals](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/renderer-feature-decal-reference.html): local wear is available but requires renderer configuration. **Deferred**: source architectural inconsistency and screen occupation are more important than seam dirt; avoid mobile prepass dependency until one local proof improves frame.
- [Unity graphics optimization](https://docs.unity3d.com/6000.3/Documentation/Manual/OptimizingGraphicsPerformance.html): proof uses a small set of low-triangle visual strips, no new lights/transparent field particles/colliders. **Deferred** production performance certification to physical device; CI screenshot is not FPS evidence.

Toolchain route `environment_composition` via `tools/plan-art-production.mjs`: Unity assembly first, Blender source workflow available but prior semantic family rejected visually; no new plugin, paid tool, Tripo, or inferred need for regenerated geometry. One reversible whole-frame hypothesis: connect Hero approach → civic core → functional service route → cultivated outside, with compatible source-rich stone/dirt materials and protected parcels. If this reads as artificial strips or does not close the global gap at real 19/12/9/mobile, reject it and do not proliferate modules. This is not color-only tuning.

## Toolchain outcome

The existing Unity 6 URP response, source CC0 maps, deterministic gate and shared Windows runner successfully established a reproducible whole-frame falsification. Blender was not invoked in this block because the prior authored-secondary proof had already demonstrated technical mesh/material authoring and visually rejected its first family; pretending that another parameter tweak of the same source-atlas were a distinct hypothesis would be misleading. No plugin or generation service was adopted. The missing capability is a *new authored full-frame design system* with source richness and camera-composition art direction, then actual multi-source asset construction—not evidence that Blender, Unity or the Flat Citadel topology cannot do it.
